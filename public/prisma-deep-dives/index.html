V3 / The recipe
Try this in your codebaseA four-step recipe for finding and checking unnecessary Prisma type work.

1. Save a cold baseline. Run your type check with --incremental false --extendedDiagnostics. Record total time, check time, and instantiations. Keep the compiler, generated client, dependencies, machine, and settings fixed for the comparison. Instantiations count compiler work, not runtime objects.

2. Check what you actually configure. We never used global field omissions, so we made that constraint explicit. If you use global omit, preserve it. Inspect your generated client's declarations before adapting this example: generic positions depend on the Prisma version. Keep your existing adapter setup and logging configuration.

3. Follow the client through your helpers. Apply the same omission contract at each constructor and extension boundary. For helpers that use one model, request that model: our document-number helper accepts Pick<Prisma.TransactionClient, "organizationSequence">. The undefined above is a type argument; it does not remove fields at runtime.

4. Verify, then remeasure. Add a type regression check for the omission contract, run transaction and extension tests, and compare emitted JavaScript. Repeat the cold baseline. Our gain came from the combined changes; a smaller helper signature alone does not promise the same result.
